## Attributes NOT verifiable by query source alone

The AC2 originally listed 8 required attributes. Of those, 6 are verifiable in the query source
(Opportunity Amount + CloseDate + Constituent + Fund + Description + FDA count). The remaining 2
require verifying the LOAD in Salesforce:

- Payment record with method "Check" and number "214" → NOT in donation_transaction.sql; comes from
  `opportunity_payments.sql` which follows the fund fix cascade. Predicted post-load: a Payment record
  linked to Opportunity CB62A0CA with Payment Method "Check" and Check Number "214".
- Recognition/soft credit CBIZ $25,000 → comes from `npsp_partial_soft_credit.sql` or
  `npsp_account_soft_credit.sql`. Both queries share the same EligibilityGate and are patched in this PR.

The PR body states: "Loading the rescued gift into the org and deleting the already-loaded duplicate
are not part of this PR." So the QUERY source is validated (the gift is now visible to the extractor),
but the actual Salesforce load is a separate step — that's why the PR gives the External IDs
`CB62A0CA...` and `FC314D94...` as PREDICTED IDs "on the next run".

## Evidencia code diff

The single-line change that rescues rev-10059094:
```
COALESCE(own_split_ext.APPLICATION, superseded_split_ext.APPLICATION)
```
Applied in the EligibilityGate of the 5 shared-gate SQL files. The replacement line, previously invisible
because it had no REVENUESPLIT_EXT row of its own, now inherits the superseded line's `APPLICATION='Donation'`
and survives the eligibility gate.
