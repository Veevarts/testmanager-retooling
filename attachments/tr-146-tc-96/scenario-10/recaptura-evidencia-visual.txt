HALLAZGOS NUEVOS DE ESTA PASADA (no estaban en la primera)

1. VALIDACIÓN DE UI QUE LA API NO EXIGE — "Start Date" obligatorio en el formulario.
   El primer intento de "Create" fue rechazado en el browser con:
       "Please choose the Start Date for this survey."
   Sin embargo las generales 19, 20 y 21 de la primera pasada se crearon por API SIN Start Date y
   la API las aceptó (201). O sea: la UI es MÁS estricta que la API en este campo.
   Severidad: baja. No es un defecto funcional —el campo tiene sentido de producto— pero es una
   asimetría de validación: un cliente que use la API directamente puede crear surveys en un estado
   que la UI considera inválido. Se reporta como observación, no como defecto.

2. COMPAT LEGACY CONFIRMADA EN VIVO — con UNA sola organización seleccionada, el formulario
   persiste `generalClientOrgId: "computing-power-944-dev-ed"` ADEMÁS de
   `audience: "organization"` y `audienceDetails`. Se ve literalmente en 03-eligibility-response.png.
   El escenario 9 lo dejaba como "opcional, solo si querés dejarlo documentado" — queda confirmado.

3. `generalTrigger` NO se escribe en triggerDetails cuando se elige el modo por defecto.
   La 22 quedó con `triggerDetails: "cooldownDays=90, onePerRespondent=true"`, SIN
   `generalTrigger=featureTrigger`. Verificado que igual se comporta como featureTrigger:
       GET /api/features/rentals/surveys  -> [{id 22, GENERAL}]
       GET /api/surveys/general/eligible  -> []
   O sea la ausencia de la clave equivale a featureTrigger. Es coherente, pero significa que
   `triggerDetails` no es una fuente confiable para saber el modo de una general: hay que asumir
   featureTrigger cuando la clave falta. Dato útil para quien depure esto después.

4. PRUEBA VISUAL DEL HALLAZGO DE SEGURIDAD BAJO (A01/A05).
   03-eligibility-response.png es evidencia directa de lo reportado en owasp-top10-scan.txt: la
   respuesta del endpoint público ANÓNIMO incluye `audienceDetails` y `generalClientOrgId`, o sea la
   organización objetivo de la survey, además de `maxDismissals`, `triggerDetails` y `active`.
