EL CAMBIO
---------
  rental_resource.sql unia SALESORDERITEMTAX en crudo, que tiene una fila por (item, impuesto). Un
  item con dos impuestos producia dos filas con el MISMO external id, cada una cobrada a una sola tasa.
  El PR la reemplaza por RentalResourceItemTaxes (SUM(TOTALTAX) por item). Verificado en el diff: es el
  unico cambio del export de recursos, y su SELECT final no cambia.

LO QUE LOS DATOS REALES ALCANZABLES PERMITEN VER
------------------------------------------------
  Items de alquiler con mas de una fila de impuesto:
      Long Island      0   (ademas 0 filas de impuesto en total)
      Vizcaya          0   (3.890 filas de impuesto, todas de una sola tasa)
      Illinois, MOAD, Kidstream 1, Kidstream B2: no conectaron

  O sea el defecto de duplicados NO existe en los datos de estos dos clientes, y no se puede
  reproducir con datos reales.
