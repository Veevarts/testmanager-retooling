Technical + Security regression plan — PR #211 (MigrationAppBackend)
=====================================================================

Change surface: 1 file. JSON spec seed rewrite (v1 → v3). No code, no SQL,
no schema, no infra. The Apex is EMBEDDED as string in the JSON
inputPayload.apex fields; it runs inside T6 tool at case-execution time
against the target org (illinois-trainings for QA).

Blast radius
------------
- Runtime: Apex executed by T6 tool via anonymous Apex against the target
  org. Reads + writes: Auctifera__Batch_Settings__c (custom setting org
  default), vnfp__Fundraising_Settings1__c (custom setting org default),
  CronTrigger (via System.schedule), AsyncApexJob (via Database.executeBatch).
- Dependencies: none (dependsOn []). Master template runs 9.2 AFTER
  ic-4-05 (Roundup/Fee funds owned by 4.05); standalone here does not
  duplicate that logic.
- Sibling cases affected: none removed / renamed. Same caseId
  ("ic-9-2-accounting-batches"); publisher will overwrite v1 with v3.
- MigrationApp UI: no changes to consumer contract (still returns 4 steps
  though shape differs — 3 AUTOMATED + 1 MANUAL vs prior 1 AUTOMATED +
  1 MANUAL). Callers that count steps or care about specific stepIds
  may need adjustment (see item T3 below).
