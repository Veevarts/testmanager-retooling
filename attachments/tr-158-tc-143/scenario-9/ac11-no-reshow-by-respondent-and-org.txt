AC11 PASS: the eligibility cutoff after a response is applied by (respondent, org)
tuple, not by org alone. A fresh respondent in the SAME org still sees the survey;
the respondent who answered no longer does. Server-side agrees with the client-side
sessionStorage guard.

Side finding (not a blocker for AC11, but relevant to IM-1165):
  the release adds a `salesforceOrgId` parameter to /eligible and expects the launcher
  to send the raw Salesforce Org Id (00DRt00000TAlrNMAT). The current bundle sends
  clientOrgId=flow-site-19432-dev-ed, and the eligibility check on the raw org id
  returns [] for both the original AND the OTHER respondent — which means either
  (a) the survey audience is not yet keyed by the raw org id, or
  (b) the release also updates that keying and the two migrations must land together.
  This is validated by the release code path but NOT by this scratch, which still
  has the pre-#2234 vnfp package. Documented for the dossier, not counted against
  AC11.
