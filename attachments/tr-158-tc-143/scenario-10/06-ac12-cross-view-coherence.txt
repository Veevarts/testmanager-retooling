------------------------------------------------------------------------------
Fidelity finding kept from TR-157 and re-confirmed today
------------------------------------------------------------------------------

The Auctifera clientOrgId is persisted LOWERCASE (`00dem00000v5erwmaz`) instead
of the canonical uppercase (`00DEm00000V5eRWMAZ`) that Salesforce uses. For a
15-character Org Id the case matters (14-bit case bits encode into the 18-char
suffix), and `hasActiveOrganization` compares by exact string, so a lookup with
the uppercase form MAY miss the response record. In the current release the
launcher and the launcher-callers normalize by lowercasing, so no data is lost
today — but a future consumer that passes the raw uppercase Id will read `[]`.
Worth adding a documented normalization step at the persistence boundary (or a
one-off migration + comparison change to case-insensitive).

VNFP's client_org_id is stored as `flow-site-19432-dev-ed` (org host alias)
because the scratch runs the pre-#2234 vnfp package — after #2234 lands, both
orgs will present the raw Salesforce Org Id (the IM-1165 contract) and this
lowercase vs uppercase divergence will surface immediately across sources.
