------------------------------------------------------------------------------
UX finding (not a defect, but worth flagging for the release dossier)
------------------------------------------------------------------------------

The compact inline Edit view opened via the list's "Edit" button surfaces only the
main question and the card-level configuration (subject/type/audience/dates/
interactions/repeat/layout/active). It does NOT expose the follow-up-question label,
brand question, follow-up options, custom questions, or advanced delivery limits
inputs — those live in the multi-section "Create survey" wizard and can only be
edited by re-opening the full form (or via API).

Nothing is silently lost: those fields ARE persisted server-side and DO show up on
the survey preview and the public /survey/rentals endpoint. This is a design
constraint of the compact edit and would only be a concern if an operator expects
to fine-tune the follow-up label from the list quick-edit.
