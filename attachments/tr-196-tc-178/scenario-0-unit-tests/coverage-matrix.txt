NOTA DE ENTORNO — LA PRIMERA CORRIDA FALLO, Y NO FUE EL PR

  La primera ejecucion del spec de docker dio 18/18 FAIL, todos con el mismo mensaje:
  "Log message 'SQL Server is now ready for client connections' not received after 60000ms".
  Se conserva ese log en integration-docker-FIRST-RUN-env-timeout.log en vez de ocultarlo.

  Antes de atribuirlo a nada se midio: se arranco el mismo contenedor a mano y SQL Server
  tardo 94 SEGUNDOS en quedar listo, contra los 60 que el spec espera por defecto. La
  maquina tiene el runtime de contenedores con 4 CPU y 6 GiB y otros dos contenedores
  corriendo. Es entorno, no codigo, y no se reporta como defecto del PR.

  Para poder ejecutar igualmente los tests se subio EN LOCAL y de forma temporal el timeout
  de arranque del contenedor (`.withStartupTimeout(300000)`), se corrio, y se revirtio el
  archivo. Solo se toco cuanto se espera a que la base arranque; ninguna asercion se
  modifico. El spec que se mergea sigue teniendo los 60 s por defecto.

  Observacion menor que se deriva de esto (F4 en findings): 60 s de margen para arrancar
  SQL Server 2022 es ajustado. En una maquina cargada o en un runner de CI compartido, esa
  suite falla por tiempo sin que nada del producto este mal. Subir ese timeout en el propio
  spec ahorraria diagnosticos falsos.
