## Evidencia fixture (charge-without-order-query.spec.ts, 21 tests PASS)

The four tests in "POS Purchase reference (IM-1192)" describe block:

1. **"resolves the reference per object family instead of always using the bare transaction id"** —
   asserts the CASE now contains all 5 per-family branches (`rental.PaymentId`, `payment_so.ID`,
   `pledge.TxnId`, `membership_pos.PosExternalId`, `donation.TxnId`).

2. **"leaves the reference NULL when no family resolves a purchase"** — asserts `ELSE NULL` after
   the donation branch.

3. **"casts every branch of the reference to NVARCHAR"** — asserts no `THEN ft.ID` or
   `THEN payment_so.ID` bare id branches. Pins the IM-770 uniqueidentifier-precedence trap.

Plus the 4 tests in "family gates mirror their POS queries (IM-1192)" block ensure each branch's
gate matches its minting POS Purchase query exactly, so a Charge cannot name a key that query would
not have emitted.

## Evidencia code diff (charge_without_order.sql +533/-60 lines)

The old (pre-IM-1192) code projected a single bare `ft.ID` for every family:

    -- OLD:
    -- ('Auctifera__POS_Purchase__r:Auctifera__POS_Purchase__c-Implementation_External_ID__c', ft.ID),
    -- fails 77% of rows because pos_purchase queries key their purchases on 5 different formats.

The new code (SELECT projection block):

    CAST(CASE
      WHEN rental.PaymentId IS NOT NULL THEN CAST(rental.PaymentId AS NVARCHAR(100))
      WHEN payment_so.ID IS NOT NULL THEN CAST(payment_so.ID AS NVARCHAR(100))
      WHEN pledge.TxnId IS NOT NULL THEN CAST(pledge.TxnId AS NVARCHAR(100))
      WHEN membership_pos.PosExternalId IS NOT NULL THEN CAST(membership_pos.PosExternalId AS NVARCHAR(100))
      WHEN donation.TxnId IS NOT NULL THEN CAST('donation-no-order-pos-' + CAST(donation.TxnId AS NVARCHAR(100)) AS NVARCHAR(100))
      ELSE NULL
    END AS NVARCHAR(100)) AS 'Auctifera__POS_Purchase__r:Auctifera__POS_Purchase__c-Implementation_External_ID__c'

Each family's key expression exactly mirrors the minting POS Purchase query.
