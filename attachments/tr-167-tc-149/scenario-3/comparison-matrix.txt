## Evidencia fixture (charge-without-order-query.spec.ts describe: grain)

4 tests en el describe "grain" del spec:

1. **"emits one Charge per payment and prefers the row that resolves a purchase"** — pinnea que
   la query aplica `ROW_NUMBER() OVER (PARTITION BY COALESCE(chargeRevenue.ID, ft.ID)...) AS ChargeRank`
   + `WHERE q.ChargeRank = 1`.

2. **"reduces REVENUEPAYMENTMETHOD to one row per revenue so the rank is deterministic"** —
   pinnea el `PaymentMethods AS (... MIN(ID) AS ID FROM REVENUEPAYMENTMETHOD GROUP BY REVENUEID)`
   guard (F-6). Sin este guard, `REVENUEPAYMENTMETHOD` produce fan-out y el rank ordena por una
   columna no-única → non-idempotencia.

3. **"does not join tables it never projects"** — asserta que las 4 tables eliminadas
   (`PAYMENTORIGINALAMOUNT`, `ADJUSTMENT`, `CREDITPAYMENT`, `CASHPAYMENTMETHODDETAIL`) ya no
   aparecen en el SQL. Tres de esas 4 eran fan-out sources adicionales.

4. **"still exports the charge keyed on the payment transaction"** — asserta que el external id
   sigue siendo `COALESCE(chargeRevenue.ID, ft.ID)` (grain preservado).

## Evidencia code diff — el rank + los guards

Del diff (líneas del `PaymentMethods` CTE y `ChargeRank`):

    PaymentMethods AS (
      SELECT rpm.ID, rpm.REVENUEID, rpm.PAYMENTMETHOD
      FROM REVENUEPAYMENTMETHOD rpm
      JOIN (
        SELECT REVENUEID, MIN(ID) AS ID
        FROM REVENUEPAYMENTMETHOD
        GROUP BY REVENUEID
      ) rpm_first ON rpm_first.ID = rpm.ID
    )

    -- Final SELECT wrapper:
    SELECT ... FROM (
      SELECT
        ...,
        ROW_NUMBER() OVER (
          PARTITION BY COALESCE(chargeRevenue.ID, ft.ID)
          ORDER BY <total-order preferring rows that resolve a purchase>
        ) AS ChargeRank
      FROM ...
    ) q
    WHERE q.ChargeRank = 1
