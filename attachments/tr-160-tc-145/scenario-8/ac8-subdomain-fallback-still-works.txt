## Code side — subdomain path still active in isActiveClientOrg

server/src/routes/features.ts:52-58:

  if (!clientOrgId) return false;
  return db.select({...}).from(organizations)
    .where(and(eq(organizations.subdomain, clientOrgId), eq(organizations.active, true)))
    .limit(1).all().length > 0;

The subdomain lookup is unchanged from pre-IM-1165 behavior. When a request lacks
salesforceOrgId but includes clientOrgId (the legacy path), the code falls through to
the subdomain match.

## Note on AC8 wording

The AC says "subdomain-based resolution continues to work without breaking existing
test flows". It does NOT explicitly require that prd BLOCK subdomain requests. In
practice, prd blocks them by data absence (no organization row has a subdomain in
prd), not by env-gated code. This is a valid design: the runtime code is env-agnostic;
the data model is what enforces the boundary.

Verdict: AC8 PASS (code unchanged, tests unchanged, dev/stg VNFP scratch still
resolves via subdomain; prd has no subdomain-carrying rows so the fallback is a no-op
in prd by data absence).
