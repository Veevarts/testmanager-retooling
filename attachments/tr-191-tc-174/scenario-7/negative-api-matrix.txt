Escenario 7 — actuar dos veces, o fuera de orden, falla cerrado
===============================================================
Ejecutado contra el backend de dev con la sesion del navegador,
sobre la sugerencia 24d4de75-c7f0-4fc9-812f-90c309b5f832.

  accion                                   | HTTP | respuesta
  -----------------------------------------|------|--------------------------------------
  POST /complete sobre una sugerencia      | 409  | "Invalid task transition: Suggested →
                                           |      |  Done. Allowed from Suggested:
                                           |      |  [New, Rejected]."
  POST /restore sobre algo no borrado      | 409  | "Task ... is not deleted."
  POST /decline (primera vez)              | 201  | task.state = Rejected
  POST /decline (segunda vez)              | 409  | "Task ... is already deleted."
  POST /accept despues de declinar         | 409  | "Task ... is deleted; restore it before
                                           |      |  changing its state."
  POST /restore (devolver el entorno)      | 201  | task.state = Suggested

  Ningun 500, ningun 200 silencioso, ningun registro a medias. El mensaje del primer caso
  enumera las transiciones permitidas, que es la regla del ticket dicha por el producto:
  desde Suggested solo se llega a New (aceptar) o Rejected (declinar). "Hecha" no esta.

  El entorno quedo como estaba: la sugerencia volvio al panel.
