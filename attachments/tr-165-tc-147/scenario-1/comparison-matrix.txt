Note on determinism (AC1 formats):
- Key format: `donation-no-order-pos-<RecurringInstallmentID or FinancialTransactionID>` where the
  inner ID is CAST NVARCHAR(36) — matches the standard Altru GUID representation.
- Prefix is a compile-time literal, not derived from data — same on every run.
- The inner ID comes from Altru's own PK (RecurringInstallmentID for recurring gifts, else the
  transaction ft.ID). Both are Altru-stable identifiers — the key is deterministic across runs.
