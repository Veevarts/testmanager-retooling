AC2 — crear una tarea a mano con los seis campos, y que sobrevivan una recarga.

EL FORMULARIO OFRECE LOS SEIS
  Title*        obligatorio ("Create task" queda deshabilitado sin el)
  Description
  Account       con opcion explicita "No account" + "Optional — a task can belong to no account."
  Due
  Column        <-- hace de "status"
  Priority

LO QUE SE ESCRIBIO -> LO QUE QUEDO (releido del servidor tras recargar la pagina)

  campo         escrito                                   releido                          igual
  title         QA TC-176 · tarea completa con los seis…  QA TC-176 · tarea completa con…  si
  description   Creada por QA para IM-1239 AC2: …         identica                         si
  account       Krasl Art Center                          Krasl Art Center                 si
  dueDate       2026-09-22                                2026-09-22                       si
  priority      High                                      urgency "high"                   si
  column        In progress                               column "doing" / state In_progress si

  id aef92e95-a48a-4c2f-929b-39690641fd93 · origin "manual" · sfCaseId null

  Ningun valor se perdio y ninguno se reemplazo por un default. La tarjeta aterrizo
  en la columna elegida (In progress), no en To do.

  POST /csm/tasks -> 201. Cuerpo enviado:
    {"accountId":"1d18b50f-...","title":"...","description":"...",
     "dueDate":"2026-09-22","column":"doing","urgency":"high"}
  Con cuenta NO se manda ownerId, que es la regla que el servidor exige.

HALLAZGO F1 — los dos formularios no ofrecen lo mismo (ver findings.txt)
  crear:  Column  [To do, In progress]        Priority [Low, Medium, High]
  editar: State   [To do, In progress, Done]  Urgency  [Low, Medium, High, Critical]

  La diferencia de COLUMNA es deliberada y el servidor la respalda:
      POST /csm/tasks {"column":"done"} -> 400
        "column must be one of the following values: todo, doing"
      Una tarea que se crea no esta ya terminada. No es defecto.

  La diferencia de PRIORIDAD no tiene respaldo:
      POST /csm/tasks {"urgency":"critical"} -> 201
      El servidor la acepta; el formulario de creacion no la ofrece. Un CSM no puede
      crear una tarea Critical: tiene que crearla y despues editarla.
