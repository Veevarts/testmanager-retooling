AC4 — una tarea sin cuenta y sin caso de Salesforce.
Este es el criterio que el 2026-09-16 se certifico como cumplido LEYENDO EL CLIENTE
y estaba roto en el servidor. Aqui no se lee ningun cliente: se mide la respuesta.

1. CREACION POR LA PANTALLA  (opcion "No account", solo el titulo)
   POST /csm/tasks  -> 201
   cuerpo enviado:
     {"title":"QA TC-176 · tarea sin cuenta ni caso SF","column":"todo",
      "urgency":"medium","ownerId":"005Vs000005Dh2fIAC"}
   El cliente manda ownerId, que es precisamente lo que el PR 197 anadio.

   Fila releida del servidor:
     id 98757323-a8c7-411c-a57f-cb06ead13981
     accountId null · accountName null · sfCaseId null · origin "manual"
     state New · column todo
   Sin cuenta, sin caso, y con dueno.

2. EL DEFECTO ORIGINAL, REPRODUCIDO HOY
   Se repitio la MISMA llamada quitando ownerId — que es literalmente lo que el
   cliente enviaba antes del PR 197:
     POST /csm/tasks {"title":"...","column":"todo","urgency":"medium"}
       -> 400
       "Could not determine the owning CSM for an account-less task.
        Pass ownerId, or create the task against an account."

   El servidor NO cambio. El arreglo fue que el cliente empezara a mandar ownerId.
   Sin ese dato, el fallo sigue ahi, exactamente como lo encontro el product owner.

3. LA CONTRADICCION QUE EL SERVIDOR DEBE RECHAZAR
     POST /csm/tasks {..., "accountId":"1d18b50f-...", "ownerId":"005Vs0000..."}
       -> 400
       "ownerId cannot be combined with accountId: a task with an account is
        owned by that account's CSM."

   Y en la creacion CON cuenta (escenario 2) el cliente efectivamente NO manda
   ownerId, asi que las dos reglas encajan.
